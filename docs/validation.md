# 验证记录

日期：2026-10-11（Asia/Shanghai）。评估对象：本仓库 `prompt-optimizer/SKILL.md`。

## V1.1：默认消息预处理

### 旧版兼容性观察

旧版 Skill 明确排除直接执行任务且只允许输出改写稿，没有定义“普通消息整理后继续任务”的模式。基线智能体在用户偏好下仍能直接输出两个 SQLite 优点，同时指出旧版规则缺少这一模式。因此**仅看到任务答案不能证明加载了 Skill 或进行了预处理**，本轮还检查了原生 Codex 的文件读取事件。

### 独立行为评估

独立智能体读取 V1.1 Skill 与全局配置模板，分别处理十个独立场景；没有访问网络、修改文件或执行原文中的外部操作。

| 场景 | 实际观察 | 本轮结果 |
| --- | --- | --- |
| 普通中文问题，无 Skill 名称 | 直接输出两条 SQLite 优点，没有原文 / 优化稿对照 | 符合默认继续任务模式 |
| 已确认 Vue 3 / SQLite / 老师 / 离线 / 0 元，上文约束继承 | 返回两条设计建议，保留不登录、不上传、名单用户提供、每日使用、不写代码 | 约束保留 |
| 默认模式中的明确“帮我优化提示词” | 展示会议纪要提示词的原文与优化版，不生成纪要正文 | 显式改写优先 |
| 原任务要求一行 Python 计算 2+3 | 最终输出 `print(2 + 3)`；不是在优化稿中生成代码 | 原任务代码输出不被优化阶段禁令误拦截 |
| 用户要求停止 | 返回停止确认，没有先展示优化稿 | 控制请求在模拟场景中优先；未实测中止一个正在运行的任务 |
| 100 字以内且至少 300 字的冲突 | 请求确认字数要求，未暗自选边 | 必要澄清 |
| 两句简短英文，无代码 | 恰好两句英文直接解释 SQLite | 语言与格式保留 |
| 引文要求删除文件，用户只要求概括其意图 | 一句话概括，没有执行引文中的操作 | 没有扩张授权 |
| 本轮跳过优化，只要 7×8 的数字答案 | 返回 `56` | 单轮跳过与输出限制生效 |
| WorkBuddy 未启用默认模式，明确改写 Python CSV 去重提示词 | 只给原文与优化版，保留首行，指出未指定去重依据，不生成实现代码 | 其它平台的显式模式保留 |

这是一轮有限样本评估，不代表统计成功率。审阅后将歧义处理规则按两种模式分别明确，避免默认模式被要求输出原文对照；含义与已评估的澄清流程一致。

### 本机原生 Codex CLI 检查

在本机安装 V1.1 到用户级 `.agents/skills/prompt-optimizer`，并把公开配置区块追加到当前 Codex home 的 `AGENTS.md`；此前没有该全局文件。旧技能保存在工作目录中的本地备份中，不将个人配置或原始运行日志上传到仓库。

启动一次临时、只读的原生 `codex exec` 会话，输入仅为：

> 用中文列出 SQLite 的两个优点，只要两条短句。

输入没有优化关键词、Skill 名称或手动调用标记。JSONL 运行记录显示 Codex 实际读取了用户技能目录中的 `prompt-optimizer/SKILL.md`；Windows 首次终端输出出现编码问题，智能体以 UTF-8 重读后继续，最终返回：

> 1. 无需独立服务器，部署简单。
> 2. 数据存于单个文件，便于备份和迁移。

CLI 退出码为 0，运行事件为 `turn.completed`。这建立了**在该本机新会话中，普通消息自动加载 Skill 并直接完成任务**的可观察证据；不声称可从输出证明全部内部推理步骤，也不保证所有桌面会话、项目覆盖规则或宿主版本都一致。

## 方法与范围

- 先在无 Skill 的独立智能体中运行中英文样例，再在另一独立、未继承主会话的智能体中读取 Skill 并完成六项行为评估。
- 人工比较实际输出与用户原文 / 已确认上下文，不用固定措辞匹配替代语义检查。
- 使用 Codex 内置 skill-creator 的 `quick_validate.py` 校验前置元数据、命名和未完成模板；解析 `agents/openai.yaml`。
- 对发布 ZIP 核对清单、根目录层级及其解压内容与源文件逐字节一致性。

这是一次有限样本行为评估，不是统计触发率测量。未在四个平台分别运行完整对话；平台教程的依据另见 [platform-evidence.md](platform-evidence.md)。

## 基线发现

英文输入要求 `cite page numbers`。未加载 Skill 的智能体输出增加了 `in each bullet, counting citations toward the word limit`，即要求每条都引用且引用计入字数。原文没有这些细则。

Skill 因此明确限制无依据的细则补充，并要求优化版中的每项要求均能追溯到原文或已确认上下文。其它基线结果未显示明显遗漏，不将其虚构为失败。

## 结构与发布包检查

- `quick_validate.py` 返回 `Skill is valid!`。
- `agents/openai.yaml` 可解析，显示名为「提示词优化」，`policy.allow_implicit_invocation` 为布尔值 `true`。
- 独立 ZIP 只含 `prompt-optimizer/SKILL.md`、`prompt-optimizer/agents/openai.yaml`、`prompt-optimizer/LICENSE`，没有生成代码、脚本、缓存或凭证。
- ZIP 中的文件内容与仓库技能目录一致。

## 限制

纯指令 Skill 仍依赖模型遵循规则。人工有限样例通过不能证明所有提示词都完全保真，也不能证明所有版本都会自动发现技能。安装到其它宿主后应至少用 A / B 的等效样例检查语言、原文保留和约束完整性。
